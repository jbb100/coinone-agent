# Commit Message Generator

일관된 Conventional Commits 형식의 커밋 메시지를 생성합니다.

## Instructions

변경 사항을 분석하고 프로젝트 규칙에 맞는 커밋 메시지를 생성합니다.

### 1. 변경 사항 분석

먼저 `git status`와 `git diff --staged`를 실행하여 변경 사항을 파악하세요.
staged 변경사항이 없으면 `git diff`로 unstaged 변경사항을 확인하세요.

### 2. 커밋 타입 선택

| 타입 | 설명 | 예시 |
|------|------|------|
| `feat` | 새로운 기능 추가 | 새 모듈, 새 API 엔드포인트 |
| `fix` | 버그 수정 | 에러 수정, 로직 오류 수정 |
| `refactor` | 코드 리팩토링 | 구조 변경, 성능 개선 (기능 변화 없음) |
| `test` | 테스트 관련 | 테스트 추가, 테스트 수정 |
| `docs` | 문서 변경 | README, 주석, docstring |
| `style` | 코드 스타일 | 포맷팅, 세미콜론, 공백 |
| `chore` | 빌드/설정 변경 | 의존성, CI/CD, 설정 파일 |
| `perf` | 성능 개선 | 알고리즘 최적화, 캐싱 |

### 3. 커밋 메시지 형식

```
<타입>(<스코프>): <제목>

<본문 (선택)>

<푸터 (선택)>
```

**규칙**:
- 제목은 50자 이내로 작성
- 제목은 명령형으로 작성 ("추가함" X, "추가" O)
- 본문은 72자 단위로 줄바꿈
- 본문에는 "무엇을", "왜" 변경했는지 설명
- 한국어로 작성

### 4. 스코프 가이드

이 프로젝트의 주요 스코프:

| 스코프 | 설명 |
|--------|------|
| `trading` | 트레이딩 로직, 전략 |
| `risk` | 리스크 관리 |
| `api` | API 클라이언트, 외부 연동 |
| `indicators` | 기술적 지표 (RSI, MACD 등) |
| `backtest` | 백테스팅 관련 |
| `data` | 데이터 처리, 검증 |
| `config` | 설정 관련 |
| `core` | 핵심 모듈 |

### 5. 좋은 커밋 메시지 예시

```
feat(trading): DCA 전략에 변동성 기반 매수량 조절 추가

- ATR 지표를 활용한 변동성 측정
- 고변동성 시 매수량 50% 감소
- 저변동성 시 매수량 30% 증가

Closes #42
```

```
fix(risk): 포지션 사이징 계산 시 슬리피지 미반영 수정

손절가 계산 시 슬리피지(0.2%)를 고려하지 않아
실제 리스크가 설정값보다 높았던 문제 수정
```

```
refactor(indicators): RSI 계산 로직 Wilder's smoothing으로 변경

기존 단순 EMA 대신 표준 RSI 공식인 Wilder's smoothing 적용
```

```
test(backtest): 슬리피지 및 수수료 포함 테스트 케이스 추가

CLAUDE.md 백테스팅 체크리스트 반영
- 0.1-0.3% 슬리피지
- 거래당 0.2% 수수료
```

### 6. 나쁜 커밋 메시지 예시

```
# 너무 짧고 정보 없음
bugfix

# 타입 없음
버그 수정함

# 너무 김
feat: 사용자 인증 시스템에서 발생하던 토큰 만료 관련 버그를 수정하고 리프레시 토큰 로직을 개선하여 사용자 경험을 향상시킴
```

## Output Format

```
## 추천 커밋 메시지

### 변경 사항 요약
- [변경된 파일 목록]
- [주요 변경 내용]

### 커밋 메시지
```
<타입>(<스코프>): <제목>

<본문>
```

### 커밋 명령어
```bash
git add <files>
git commit -m "<message>"
```
```

## 자동 커밋 실행

사용자가 "커밋해줘" 또는 자동 실행을 요청하면:
1. 변경 사항 분석
2. 커밋 메시지 제안
3. 사용자 확인 후 `git add` 및 `git commit` 실행

$ARGUMENTS
